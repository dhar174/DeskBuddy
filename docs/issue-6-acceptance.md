Independent verification review checked the production call path, the lost acknowledgement scenario, isolation, and optional service prerequisites. Its recommendations on canonical temporary paths, preloaded runtimes, and documentation were incorporated.

## Legacy limits identified in review

- **Utterance identity:** The harness now publishes transcripts through `send_response()` and verifies that polls return an unconsumed transcript again. Distinct consecutive utterances with identical text are still conflated, and a restarted client can see a stale transcript. A follow-up should define utterance identity and delivery/acknowledgement semantics across desktop and Windows adapters before changing the polling protocol.
- **Audio and device lifecycle:** The contracts reach the speech driver call with a fake; they do not run PyAudio capture, Whisper recognition, or real synthesis. Stream cleanup on failure, sample-rate requirements, playback/capture coordination (echo prevention), LED restoration, cancellation/chunking, and background servo error handling need dedicated audio and hardware verification.
- **Runtime and persistence:** Blocking legacy inference, cloud SDK, audio and file calls still need event-loop and latency qualification. Question-bank writes are direct JSON writes; atomic replacement and corrupt-data recovery need a defined persistence policy. Local/cloud history growth and message shape, summary/save cadence, and Large-model empty decoded output need separate contracts. The desktop loop now skips a failed generation turn; it does not repair legacy model state.
